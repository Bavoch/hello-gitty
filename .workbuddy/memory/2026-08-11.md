## Hello Gitty 桌面 Git 管理工具(从零搭建)

**定位**:轻量桌面 Git 工具,为单人 AI 开发者定制。类 VS Code Git 面板但极简:全部暂存/取消暂存/提交/推送/拉取,提交信息与冲突解决全 AI。

**技术栈**:Tauri 2 + Rust 后端(git CLI 封装)+ 原生 HTML/CSS/JS 前端(无打包器,`withGlobalTauri: true` 用 `window.__TAURI__` 全局调用)。reqwest(rustls)走 OpenAI 兼容接口。

**关键文件**:
- `src-tauri/src/git.rs` — porcelain v2 解析 + 全部 git 操作(`git add -A`/`reset`/`commit -F -`/`push -u` 兜底/`pull`)
- `src-tauri/src/ai.rs` — 提交信息生成(Conventional Commits + 仓库历史风格参考)、冲突解决(读冲突标记文件 → AI 合并 → 写回 + git add,>80KB 拒绝)
- `src-tauri/src/config.rs` — 设置存 app_config_dir/settings.json(原子写)
- `src/` — 前端:文件分组(冲突/暂存/更改)、提交对话框(AI 生成可改)、冲突进度条(事件推送)、设置弹窗

**踩坑记录(重要,下次直接抄)**:
1. **crates.io 下载超时**:本项目网络到 static.crates.io 极慢(30s 传 0 字节),方案是项目级 `.cargo/config.toml` 配 rsproxy 镜像(sparse+https://rsproxy.cn/index/),1 分钟拉完全部依赖。
2. **porcelain v2 解析**:未修改状态字母是 `.`(点)不是空格;`.M` 表示仅工作区改动。一个文件 XY 为 `MM` 时应同时进 staged 和 unstaged 两个分组(VS Code 行为)。
3. **路径转义**:非 ASCII 路径被 C 风格引号包裹,八进制转义是 **UTF-8 原始字节**(带 = \345\270\246),必须按字节收集再整体 `from_utf8_lossy`,不能每个转义当独立码点。
4. **unquote 循环边界**:要处理到 `bytes.len()-1`(闭合引号)之前的最后一个字节,`i+1 < len-1` 会丢末尾字符。
5. Tauri 2 命令里用 `app.path()` 需要 `use tauri::Manager`。
6. 冲突测试要造真实冲突:同位置改同一行 + `git merge`,不能用无 remote 的 `git pull`(报的是"无远程"不是冲突)。

**状态**:单元测试 2/2 通过(生命周期 + 冲突检测)。构建产物:target/release/bundle/macos/Hello Gitty.app。
