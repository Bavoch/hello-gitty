# Checkpoint 存档点功能 — 实现计划

## 目标与范围

为单人 AI 开发者实现「手动存档点」：**打点 → AI 干活 → 一键读档回到存档点**，解决"AI 改坏了不知道怎么回去"的核心痛点。

**本次范围**：手动版（创建 / 读档 / 删除 / 列表展示）。**不在本次**：自动存档（监听工作区变化自动打点）、存档点 label 编辑界面、unborn 仓库（无首个 commit）支持——这些等手动版验证后再加。

---

## ⚠️ 关键设计决策（请重点确认）

**1. 读档语义 =「硬读档」（回退到存档点完整状态）**
- 读档时执行：`git reset --hard <存档点head>` → `git clean -fd` → 若存档时工作区有改动则 `git stash apply <存档hash>`
- 效果：HEAD 回到存档点、丢弃之后的 commit + 工作区改动、恢复存档时的工作区快照。**完全等同"游戏读档"。**
- 为什么选硬不选软：软读档（只恢复工作区不动 HEAD）在 HEAD 已前进时 stash apply 会冲突；硬读档先 reset 回 stash 的 base commit，apply 必然无冲突，更可靠。
- 因为会丢弃之后的 commit，**读档走确认弹窗**，文案明确警告"将丢弃此存档点之后的所有提交与工作区改动"。

**2. 存档点存储 = `<git目录>/checkpoints.json`**
- 用 `git rev-parse --git-dir` 解析真实 git 目录（对 worktree 友好，复用项目现有 git.rs:63-78 同款逻辑）
- 写法照抄 `config.rs`：load 静默容错（文件损坏返回空）、save 用 `.tmp` + rename 原子写
- 上限 20 条，超出删最旧的

**3. 打点用 `git stash create -u`（含未跟踪文件）**
- 工作区有改动时返回一个悬空 commit hash（不进 refs/stash 栈，不污染历史）；工作区干净时返回空 → 该存档点无 stash，读档只需 reset
- `-u` 确保 AI 新建的未跟踪文件也被快照

**4. UI 形态 = 工具栏一键打点按钮 + 时间线穿插列表**
- 工具栏加「存档点」按钮：一键打点（不弹框、默认无 label），打完 toast + 自动刷新
- 存档点条目**穿插进「版本」时间线**（按时间排序），和 commit 混排——让用户直观看到"存档点在历史的哪个位置"
- 条目复用 `.commit-row` 样式，用不同图标（旗帜）和「存档点」标签区分，hover 显示「读档」「删除」按钮

**5. 不改动 `git.rs`**
- 所有 git 调用通过 `git::run_git` 跨模块复用，降低风险。后端改动集中在新文件 + lib.rs。

## 后端实现

### 新建 `src-tauri/src/checkpoint.rs`（核心）

数据结构：
```rust
#[derive(Serialize, Deserialize, Clone)]
pub struct Checkpoint {
    pub id: String,          // epoch_nanos，唯一
    pub timestamp: i64,      // epoch 秒（前端相对时间按秒算，与 commit 一致）
    pub label: Option<String>,
    pub head: String,        // 打点时 HEAD oid
    pub stash: Option<String>, // stash create -u 的 hash，工作区干净则 None
}
```

`CheckpointStore { path: PathBuf }`（仿 `SettingsStore`）：
- `load() -> Vec<Checkpoint>`：`.ok().and_then(from_str).unwrap_or_default()` 三连容错
- `save(&[Checkpoint]) -> Result<(), String>`：create_dir_all + `to_string_pretty` + 写 `.tmp` + rename

公开函数：
```rust
pub fn git_dir(repo: &str) -> Result<PathBuf, String>  // git rev-parse --git-dir + 绝对/相对路径处理
pub fn create(repo: &str, label: Option<String>) -> Result<Checkpoint, String>
    // 1. head = run_git(rev-parse HEAD)；unborn(head 失败) → Err("请先创建第一个提交")
    // 2. stash_out = run_git(stash create -u)；stash = stash_out.trim() 非空则 Some
    // 3. 构造 Checkpoint，load 现有 → push → trim 到 20 条 → save → 返回
pub fn list(repo: &str) -> Vec<Checkpoint>  // load
pub fn restore(repo: &str, id: &str) -> Result<(), String>
    // 1. 找到 checkpoint；2. run_git(reset --hard head)；3. run_git(clean -fd)；4. stash.map(apply)
pub fn delete(repo: &str, id: &str) -> Result<(), String>  // load → retain(≠id) → save
```

单元测试（照 git.rs:604 `temp_repo` 模式，自建本地 helper）：create→改文件→restore 验证还原；含未跟踪文件场景；上限 trim；delete 生效。

## 前端实现

### `src/index.html`

1. 工具栏（:75-131）加按钮：`<button id="btn-checkpoint" class="tool-btn" title="存档点">` + 旗帜 SVG + 文案「存档点」（放在「拉取」和 busy 指示之间，或「更多」之前）
2. 加读档确认弹窗 `#dlg-restore`（复刻 :217-228 `#dlg-reset`）：标题"读档到存档点"、`.dlg-hint.warn` 警告文案、取消/确认按钮（`.tool-btn danger`）

### `src/main.js`

1. `refresh()`(:572)：把 `data.checkpoints` 透传给 `renderHistory`
2. 改 `renderHistory`(​:635)：把 checkpoints 和 commits 合并进同一数组按 timestamp 倒序，循环时判断类型——commit 走 `commitRow`，checkpoint 走新写的 `checkpointRow(cp)`
3. 新增 `checkpointRow(cp)`：复用 `.commit-row` 外壳，旗帜图标 + 「存档点」标签（indigo/accent 色）+ 相对时间 + hover 显示「读档」「删除」按钮（仿 `.rollback` 绝对定位）
4. 工具栏事件：`#btn-checkpoint` 点击 → `invoke("checkpoint_create",{repo,label:null})` → toast「已创建存档点」+ `await refresh()`
5. `askRestore(id)` / `doRestore()`：复刻 :776-800 `askReset`/`doReset`（模块级 `restoreId` 暂存，确认弹窗，`invoke("checkpoint_restore")`，loading，toast，refresh）
6. `deleteCheckpoint(id)`：`invoke("checkpoint_delete")` + toast + refresh（删除仅移除标记，直接执行不强制确认）

### `src/styles.css`

- `.checkpoint-row`（基于 `.commit-row`）：旗帜图标用 `--orange` 或 `--accent` 与 commit 区分；「存档点」标签用 `.h-head-tag` 风格
- `.checkpoint-flag` 图标样式、读档/删除按钮复用 `.rollback` 的 hover 显示模式
