## 优化切换延迟：合并后端 git 调用 + 切换即时反馈

### 问题根因
切换仓库时 `refresh()` 并行触发两个后端命令，`git_history` 内部最多 spawn **6 个** git 进程（`head_hash`、`upstream`、`ahead_count`、`behind_count`、本地 log、远程 log），分 3 段串行。叠加 `git_status` 的 1 次，单次切换最多 **7 次** `git.exe` 启动，Windows 上累积几百毫秒到 1 秒。

其中 `head_hash`/`upstream`/`ahead_count`/`behind_count` 这 4 次纯属重复——`git status --porcelain=v2 --branch` 的输出里已包含 `branch.oid`/`branch.upstream`/`branch.ab`，且 `RepoStatus` 已解析存储（`git.rs:20-33, 144-156`）。

### 改动一：后端新增 `git_refresh` 合并命令（`src-tauri/src/`）

**git.rs**
- `RepoStatus` 结构新增字段 `pub head: Option<String>`。
- `status()` 解析 `# branch.oid`（`git.rs:135`）时：非 `(initial)` 则存入 `st.head = Some(oid)`，unborn 时为 None。HEAD oid 作为 status 副产品免费拿到，取代单独的 `head_hash` 进程。

**lib.rs**
- 新增 `RefreshResult { status: RepoStatus, history: History }` 和 `async fn git_refresh(repo)` 命令（放在 `git_history` 附近，`lib.rs:309`）：
  - 阶段 1：`spawn_blocking` 跑 1 次 `git::status` → 拿到 is_repo/branch/upstream/ahead/behind/head/文件。
  - 非 git 仓库：直接返回空 history。
  - 阶段 2：用 status 的 upstream（无 upstream 时才 `first_remote_branch` 兜底，1 次进程）+ ahead/behind 算窗口，并行 `spawn_blocking` 跑 2 次 `log_ref`（本地 HEAD + 远程）。
  - 进程数：有上游 **3 次**，无上游 **2–3 次**（对比原 7 次）。
- `History` 结构加 `#[derive(Default)]`（非仓库分支返回默认值需要）。
- `invoke_handler`（`lib.rs:660`）注册 `git_refresh`。
- **保留** `git_status` / `git_history` 旧命令不删（零风险兼容，前端切走后它们不再被调用）。

### 改动二：前端 refresh 单次化 + 切换即时反馈（`src/`）

**main.js**
- `refresh()`（`main.js:242`）：内部由两次 `invoke` 改为一次 `invoke("git_refresh")`，解构 `status`/`history` 后逻辑不变。全前端约 16 处 `refresh()` 调用点自动受益（少一次 IPC 往返 + 后端少 4 个进程）。
- `switchRepo()`（`main.js:206`）：`renderRepoList()` 后、`await refresh()` 前插入 `showRefreshing()`——立即显示 loading 占位并隐藏旧 panel 内容。
- 新增 `showRefreshing()`：隐藏 `panel` 与 `empty-state`，显示 `refreshing-state`。
- `showPanel()`（`main.js:461`）和 `showEmpty()`（`main.js:440`）开头各加一行隐藏 `refreshing-state`，确保 refresh 完成后 loading 消失。

**index.html**
- 在 `#empty-state` 旁新增 loading 占位：
  ```html
  <div id="refreshing-state" class="hidden state-loading">
    <span class="spinner"></span>
  </div>
  ```

**styles.css**
- 复用现有 `.spinner`（`styles.css:279`），新增居中容器样式：
  ```css
  .state-loading { display:flex; align-items:center; justify-content:center; height:100%; }
  .state-loading .spinner { width:28px; height:28px; }
  ```

### 预期效果
- 切换仓库：点击瞬间看到 spinner → 几百 ms 后填充内容，不再有"卡住显示旧仓库"的错觉。
- 实际耗时约减半（7→3 进程，且串行段从 3 段降到 2 段）。

### 验证点
- 五种仓库形态都正确：有上游 / 无上游 / 分离 HEAD / unborn（空仓库）/ 非 git 目录。
- 历史列表的 HEAD 标记仍正确（`head` oid 经 status 透传）。
- 提交/推送/拉取/暂存/初始化后的 refresh 仍正常工作。
- 实施后跑一次 `cargo check` 确认 Rust 编译通过。

### 风险
低。后端为新增命令、不删旧命令；前端 `refresh()` 内部重构但对外语义不变。spawn_blocking 的所有权问题按现有 `git_history` 写法照搬。
