## 流式提交信息弹窗 — 实现计划

点击「提交」时,在按钮下方弹出一个轻量就地面板,实时流式显示 AI 生成的提交信息;生成完成后按现有 `commit_mode` 自动提交(confirm 模式则可编辑 + 重新生成/取消/提交)。

### 一、后端(`src-tauri/`)

**1. `Cargo.toml`** — 启用流式能力(新增 2 项):
- `reqwest` 的 `features` 增加 `"stream"`(开启 `resp.bytes_stream()`)。
- 新增依赖 `futures-util = "0.1"`(提供 `StreamExt` 驱动字节流)。
  > 会触发一次 cargo 拉取/重编译(下载两个小 crate),属正常。

**2. `src/ai.rs`** — 抽取复用 + 新增流式函数:
- 把 `generate_commit_message` 里构建 `(system, user)` 的逻辑(diff/log/lang/preset/custom)抽成 `fn build_commit_prompt(cfg, repo) -> Result<(String, String), String>`,`generate_commit_message` 改为调用它(行为不变,向后兼容 `ai_commit_message` 命令)。
- 新增 `pub async fn generate_commit_message_stream(cfg, repo, on_delta: impl Fn(&str) + Send + Sync + 'static) -> Result<String, String>`:
  - 复用 `build_commit_prompt`;
  - POST `{base}/chat/completions`,body 加 `"stream": true`;
  - 先 `resp.status()`:非 2xx 则 `resp.text()` 报错返回(流式接口出错时 body 仍是 JSON 错误);
  - `resp.bytes_stream()` 逐块读取 → 缓冲成行 → 解析 SSE `data: {...}`,取 `choices[0].delta.content`,累加成全文,每块调用 `on_delta(&accumulated)`;遇 `data: [DONE]` 结束;
  - 返回 `clean_markdown(accumulated)`(去掉模型可能裹的 ``` 围栏)。

**3. `src/lib.rs`** — 新增并注册命令:
- `#[tauri::command] async fn ai_commit_message_stream(app: tauri::AppHandle, settings: AiConfig, repo: String) -> Result<String, String>`:克隆 `app` 进闭包,`on_delta` 内 `handle.emit("commit-stream", json!({ "text": delta }))`,返回最终全文(沿用 `ai_resolve_conflicts` 的 `AppHandle` + `Emitter` 写法)。
- 在 `tauri::generate_handler![…]` 末尾 `ai_*` 分组注册该命令。

### 二、前端 HTML(`src/index.html`)

- 把 `#btn-ship` 包进 `<div class="ship-wrap">`(作为定位锚点),并在其中加入就地弹窗 `#commit-pop`(默认 `.hidden`):
  - 头部:标题 `#commit-pop-title`(「AI 正在生成提交信息…」)+ `<span class="spinner" id="commit-pop-spin">` + 关闭/取消 `×` 按钮 `#commit-pop-close`;
  - 主体:`<textarea id="commit-stream-text" disabled>`(流式期间 disabled,confirm 阶段可编辑);
  - 操作行 `#commit-pop-actions`(默认隐藏):`重新生成` / `取消` / `提交(primary)`。

### 三、前端 JS(`src/main.js`)

- **事件监听**:在 `init()` 里 `listen("conflict-progress", …)` 旁新增 `listen("commit-stream", …)`:弹窗打开且未取消时,`$("commit-stream-text").value = e.payload.text`。
- **新增状态/函数**:
  - `let popState = "idle";`(streaming / ready / idle)、`let streamCancelled = false;`。
  - `openCommitPop()` —— 显示弹窗、清空文本框、显示 spinner+标题、隐藏操作行。
  - `closeCommitPop()` —— 隐藏弹窗、复位状态。
  - `streamCommitMessage()` —— `openCommitPop()` → `streamCancelled=false` → `await invoke("ai_commit_message_stream", {settings: settings.ai, repo})`:流式期间由事件回填文本框;返回后把最终(已 clean)全文写回文本框、隐藏 spinner;`commit_mode==="auto"` → 直接 `commitWithMessage(msg)`;否则进入 ready 态(启用编辑 + 显示操作行)。catch 到错误 → 文本框可手动填写 + 提示失败。
  - `commitWithMessage(msg)` —— 空 msg 提示;`git_commit` + 成功 toast + `refresh()` + `closeCommitPop()` + `refreshShipButton()`(抽出来供 auto 与 confirm 复用)。
- **改写 `onCommit(btn)`**:保留智能暂存(`staged<total` 时先 `git_stage_all`),随后调用 `streamCommitMessage()`;移除原来对 `ai_commit_message`/`showCommitDialog` 的调用。
- **弹窗按钮绑定**:`重新生成` → 再次 `streamCommitMessage()`;`取消`/`×` → 若正在流式则 `streamCancelled=true` 软取消(忽略后续事件,后端继续跑完但不提交),否则直接 `closeCommitPop()`;`提交` → `commitWithMessage(textarea 值)`。

### 四、CSS(`src/styles.css`)

- `.ship-wrap { position: relative; }`(锚点,仿 `.branch-wrap`/`.more-wrap`)。
- `.commit-pop`:`position: absolute; top: calc(100% + 6px); left: 0; z-index: 60; width: 340px;`,主题面板样式(背景 `--panel-2`、`--border` 描边、圆角、强阴影),仿 `.commit-tip`/`.branch-menu` 的轻量浮层观感。
- `.commit-pop-head`(标题 + spinner + × 横排)、`.commit-stream-text`(mono 小字、resize:vertical)、`.commit-pop-actions`(右对齐工具按钮)三段样式。

### 五、范围与取舍

- **保留**旧的 `#dlg-commit`/`showCommitDialog`/`doCommit`/`regenMessage` 暂不删除(它们对 `pushPull` 的 pending-push 分支仍有引用)——本改动只把提交按钮主路径切到流式弹窗,旧弹窗变为休眠,降低风险;后续可单独清理。
- **软取消**:流式中点取消只在前端忽略事件并关弹窗,不中断后端请求(避免引入跨线程中断通道的复杂度);后端照常跑完、其 emit 被前端丢弃。
- **payload 用累加全文** `{ text }` 而非增量 `{ delta }`:前端直接 `textarea.value = text`,避免拼接/乱序,提交信息很短无性能问题。
- 生成完成后用后端返回的 `clean_markdown` 全文覆盖一次文本框,确保去掉 ``` 围栏。

完成后:点「提交」→ 按钮下方立刻弹出轻量面板,AI 文字逐字流入;auto 模式生成完即提交并关弹窗,confirm 模式可改可重生成可提交。
